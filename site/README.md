# Forward Deployed

The FDE interview-prep site: worksheets you fill in, with a reveal-on-demand answer
key under each section. Next.js App Router, Tailwind, no database — everything a
reader types is kept in their own browser.

## Running it

```bash
npm install
npm run dev        # runs `sync` first, then next dev
```

| Script | What it does |
| --- | --- |
| `npm run sync` | Copies the markdown out of `../15_FDE_Related_Preparation/` into `content/` and writes `content/manifest.json`. Runs automatically before `dev` and `build`. |
| `npm run check:content` | Parses every worksheet and answer key and asserts the structural invariants the UI depends on. Run this after editing any source markdown. |
| `npm run build` | Production build. |
| `npm run lint` | ESLint. |

## Content

Source markdown lives **outside this directory**, under
`../15_FDE_Related_Preparation/`. That is the only place to edit it.

`content/` is generated by `npm run sync` but is **committed anyway**: a deploy is
rooted at `site/`, so the build cannot see anything above this directory. Deleting
it or adding it to `.gitignore` will produce an empty site in production.

The interactive regions are inferred from *emptiness* in the markdown — a blank
table cell, a bare `-` bullet, a `Label:` line with nothing after the colon — never
from a scenario's name. That is why a new module becomes interactive with no code
change, and also why `check:content` exists: a stray formatting change can silently
turn an input into static text, which looks fine and is wrong.

Fenced blocks are parsed as their own blocks — ` ```mermaid ` renders as a diagram,
anything else as a code block.

## Deploying

Vercel project **`sourav-dbx/forward-deployed`**, live at
<https://forward-deployed-sigma.vercel.app>.

The project's **Root Directory is `site`**, so:

- **Pushing to `main` deploys to production automatically.** That is the normal path.
- Pushing any other branch produces a preview deployment.
- To deploy by hand, run `vercel --prod` **from the repository root**, not from this
  directory — the root directory setting is applied on top of whatever you upload.

Vercel deduplicates by commit SHA, so pushing an already-built commit onto a new
branch will not trigger anything.
