How the Technical Round Is Scored

Correctness is necessary and rarely sufficient — interviewers score four things, and three of them are invisible unless you talk.

Four scored dimensions
DimensionWhat it's really asking
Problem framingDid you restate the problem, ask about inputs, state assumptions before writing?
Solution shapeReasonable structure, and can you say why you rejected the alternative?
Production instinctsError handling, bounds, types, the failure case you handled unprompted
CommunicationContinuous narration, receptiveness to hints, honest about what you don't know
🎯 OpenAI Interview Pointer Open every problem by writing the function signature with types, then a comment block listing the failure cases you intend to handle — before any logic. Ninety seconds, and the book notes candidates who do this score higher on identical final code.

Forty Concepts, Self-Test Style — Foundations

Cover the right column. Answer aloud. Then check.

Eight foundational concept answers
QuestionAnswer at interview length
What is an agent?Pursues a goal by repeatedly selecting, executing, observing, updating state — sequence/count not fixed in advance. Discriminating property: autonomy over control flow.
Agent vs. workflow?Workflow's graph fixed at design time; agent's next step depends on what it observed. Workflows = predictable, tested. Agents = handle novelty, pay in variance.
Six components?Orchestrator, reasoning model, tool gateway, memory, guardrails, observability. Model never touches the environment directly — the gateway is the security boundary.
Why bound a loop 4 ways?Step ceiling (oscillation), token budget (giant re-read), wall clock (slow deps), no-progress detector (identical repeated calls).
Tool error vs. denial?Error = recoverable observation, feed it back. Denial = terminates the run; feeding it back invites a policy workaround.
When NOT to build an agent?Task is deterministic, verification impossible/expensive, error cost asymmetric+unbounded, or latency budget below loop time.
Why input tokens dominate cost?Full history resent each step — tokens grow ~quadratically in step count. Doubling steps ~quadruples the input bill.
The verification heuristic?Commercial viability tracks cost of checking the agent's work more than model capability. Name the oracle first.

Forty Concepts, Self-Test Style — Reasoning and Models

Eight concept answers on reasoning
QuestionAnswer at interview length
Test-time compute?Extra inference-time compute per input via deliberation/sampling/search/verification. A per-request budget you route, not a model property.
Reasoning model vs. CoT prompting?Prompting elicits tokens correlating with correctness. A reasoning model is RL-trained on checkable outcomes — deliberation IS the mechanism, robust to rewording.
Where to spend reasoning budget?The plan step — accuracy compounds multiplicatively and the plan gates every later step. Minimal effort on extraction/formatting.
ReAct vs. ReWOO?ReAct interleaves reasoning+acting, serialized. ReWOO plans once with placeholders, executes deterministically — 2 model calls, parallel, at the cost of planning pre-evidence.
When does self-consistency work?Small, discrete answer space so samples collide meaningfully. Useless for open prose.
When does reflection work?Only when the critic has an information advantage (test result, validator, extra retrieval). Same-context critic mostly agrees with itself.
Reasoning tokens?Hidden, billed, often exceed visible output on hard problems. Meter separately; alert on the ratio to output tokens.
Routing reasoning effort?Cascade: deterministic signals free → small classifier for the remainder → failed verification escalates one tier. Log the routing reason.

Forty Concepts, Self-Test Style — Tools, Context, and Memory

Twelve concept answers on the ACI, context, and memory
QuestionAnswer at interview length
Agent-computer interface?The full surface the agent perceives/affects the world through — sets the ceiling on agent reliability.
Five tool result states?Success, empty, invalid, denied, unavailable. Conflating empty/unavailable → retry storms; denied/invalid → policy workarounds.
Why filter the advertised tool list?Raises selection accuracy (shorter list) and prevents disclosing privileged tooling.
Tool count limits?Degrades past ~40. Combine principal filtering, façade namespacing, embedding retrieval, hierarchical routing.
Context engineering, defined?Systematic input construction each step: selection, compression, ordering, budget+eviction. Four ops: write, select, compress, isolate.
Why fixed section order?Byte-stable prefix → provider caching works; any step's context is reconstructable from a trace.
Global truncation danger?Truncating from the front evicts instructions/policy — long runs become a general assistant with prod credentials.
Context rot?Accuracy degrades as window fills; middle-positioned info retrieved less reliably. 3 good observations can beat 12.
Sub-agent isolation?Subtask gets its own window, returns a compact conclusion — parent grows by hundreds not thousands of tokens.
Four memory tiers?Working (window), episodic (vector), semantic (relational/graph), procedural (versioned, eval-gated).
Why not facts in a vector store?One-correct-value facts retrieved by similarity return several plausible alternatives with no way to choose. Use exact lookup.
Reciprocal rank fusion?Combine by ordinal position: Σ 1/(k+rank), k≈60. Scale-free, no normalization, stable across reindexing.
🎯 OpenAI Interview Pointer This cluster maps almost 1:1 onto Tools/Context/Memory eval dimensions. On an Agent-Evals-heavy panel, "five tool result states" and "why not a vector store" are near-certain follow-ups.

The Eight Recurring Coding Problems

Eight implementation problems recur across agentic-loop interviews — know what each tests and the extension an interviewer will layer on.

Problem → what it tests → likely extension
ProblemTestsLikely extension
1. Bounded loopTermination reasoning, result shapeAdd a 5th bound, or make it concurrent
2. Typed retryKnowing what NOT to retryHonor a server hint, share a deadline
3. Context assemblyBudgeting and eviction policyMake it cache-friendly
4. Rank fusionScale-free combination, determinismWeight retrievers, rescore with cross-encoder
5. Token bucketRate limiting, fairnessMake it distributed and atomic
6. Stream parserPartial chunks, resume, duplicatesBackpressure on a slow consumer
7. Semantic fingerprintingNormalization judgmentWhy this normalizer is wrong for a cache key
8. Trajectory evaluatorAssertions over pathsRun it deterministically in CI
Deep Dive: two traps interviewers specifically probe
Typed retry (#2): never retry a denied or invalid result. Always apply full jitter — equal or no jitter both leave retries synchronized across concurrent runs, turning a degraded dependency into an outage. Honor a server's retry-after hint over your own schedule.

Semantic fingerprinting (#7): a no-progress detector must catch an agent rewording the same query, so it sorts tokens before hashing — "did revenue exceed cost" collides with "did cost exceed revenue." Exactly right for detecting a stall, exactly wrong for a cache key using the same collision to serve a wrong answer. Progress detection wants recall; cache keys want precision — one normalizer can't serve both.

What Strong Live Coding Sounds Like

A compressed transcript pattern for any of the eight problems — six moves, each earning a specific scored dimension.

Six moves, in order
flowchart TD A["1. Restate the problem
+ confirm a key design fact"] --> B["2. Write the signature
+ failure-case comments FIRST"] B --> C["3. State the alternative
you rejected, and why"] C --> D["4. Write the simple version,
then harden it"] D --> E["5. Test aloud -
trace one case by hand"] E --> F["6. Name what you left out
('in production I would...')"]
  • Move 6 is the one most candidates skip — naming a known limitation beats hoping nobody notices it.
  • Move 3 earns "solution shape" even when the interviewer never asked for alternatives.

Recovering When It Goes Wrong

Three situations, three specific moves — narrate the recovery, don't silently patch.

What to say, in each case
flowchart TD A[You're stuck] --> A1["Say so, and say what you've ruled out.
Structured thinking scores even without a solution."] B[Design is wrong, halfway through] --> B1["Say it, state restart-vs-continue cost, then pick.
Silently patching is what's penalized."] C[You don't know a concept] --> C1["Say what you DO know adjacent to it, and how you'd find out.
Never guess confidently."]
  • Take a hint immediately, and say so ("that's a better direction, let me take it"). Defending a weaker approach after a hint costs you on receptiveness — the easiest dimension to lose.

Cheat Sheet

Scoring
4 dimensions, 3 invisible unless you narrate — signature + failure cases first, always
Concept answers
2-4 sentences, not a lecture — length isn't depth, the round is timed
Eight coding problems
Retry: never denied/invalid, always full jitter. Fingerprint: recall for progress, precision for cache keys
Live coding pattern
Restate → signature+failures → rejected alternative → simple-then-harden → test aloud → name what's left out
Recovery
Stuck: say what you ruled out. Wrong: say so, pick. Don't know: say what's adjacent, how you'd find out
