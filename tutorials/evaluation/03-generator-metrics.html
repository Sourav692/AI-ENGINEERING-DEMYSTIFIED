An answer can be perfectly faithful and completely wrong.

Faithfulness, Answer Relevancy and Hallucination all judge the generator without a reference answer — and there is one failure all three are structurally incapable of catching. Switch between four answers to the same question and find it.

Answer Correctness has no DeepEval class — you write the rubric

# Faithfulness and Relevancy ship as classes because "grounded" and "on-topic"
# mean the same thing everywhere. "Correct" does not — so DeepEval's own
# recommended pattern is a custom GEval rubric instead of a generic class.

from deepeval.metrics import GEval
from deepeval.test_case import LLMTestCaseParams

# Style 1 — criteria: one sentence, DeepEval expands it into a procedure.
correctness = GEval(
    name="Answer Correctness",
    criteria="Determine whether actual_output is factually correct relative to expected_output.",
    evaluation_params=[LLMTestCaseParams.INPUT, LLMTestCaseParams.ACTUAL_OUTPUT,
                       LLMTestCaseParams.EXPECTED_OUTPUT],
    threshold=0.7,
)

# Style 2 — evaluation_steps: you write the procedure. More controllable, and
# able to weave several test-case fields into a single rubric.
correctness_v2 = GEval(
    name="Answer Correctness",
    evaluation_steps=[
        "Check whether actual_output addresses the question in input.",
        "Compare every factual claim in actual_output against expected_output.",
        "Penalise a wrong complexity class heavily; penalise wording drift lightly.",
        "Verify each claim is also supported by retrieval_context.",
    ],
    evaluation_params=[LLMTestCaseParams.INPUT, LLMTestCaseParams.ACTUAL_OUTPUT,
                       LLMTestCaseParams.EXPECTED_OUTPUT, LLMTestCaseParams.RETRIEVAL_CONTEXT],
    threshold=0.7,
)
