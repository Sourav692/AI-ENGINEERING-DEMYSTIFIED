Three retrieval judges, three different failures.

Contextual Precision, Recall and Relevancy all score the same retrieved context, and each one is blind to what the other two catch. Inject a failure and watch exactly one number move — that separation is why DeepEval ships three metrics instead of one "retrieval quality" score.

These are LLM-judged, not the classic set-overlap Precision/Recall: Contextual Precision is rank-weighted (chunk order matters directly), and Contextual Recall checks context coverage against expected_output, not a fixed relevant/irrelevant label set. For the deterministic definitions, see 01-deterministic-retrieval-metrics.html.

What separates the three

MetricQuestionNeeds expected_output?Cares about order?Catches
Contextual PrecisionAre relevant chunks ranked above irrelevant ones?YesYesA good chunk buried under noise
Contextual RecallDoes the context cover everything the answer needs?YesNoMissing information — retrieved something, not enough
Contextual RelevancyHow much of what was retrieved is on-topic?NoNoNoise diluting the context, independent of ranking

Note the formulas: Relevancy is relevant/total — unweighted, order-blind — which is exactly classic Precision@K from 01-deterministic-retrieval-metrics.html. Contextual Precision above is the rank-weighted version of that same idea (hits-so-far/i summed over relevant positions), which is why it can diverge from Relevancy even when the two agree.

The judge produces verdicts; the score is arithmetic

# The LLM decides which chunks are relevant and which claims are covered.
# Everything after that is deterministic — which is why the same verdicts
# always produce the same score, but two judge runs may not agree on verdicts.

from deepeval.metrics import ContextualPrecisionMetric, ContextualRecallMetric, ContextualRelevancyMetric
from deepeval.test_case import LLMTestCase

case = LLMTestCase(
    input="What is Apache Spark used for?",
    actual_output="Apache Spark is a unified analytics engine for large-scale processing.",
    expected_output="Apache Spark is used for big data processing, real-time analytics, and ML.",
    retrieval_context=[...],            # the chunks your retriever actually returned
)

# Precision is rank-weighted: a relevant chunk at position i contributes
# precision@i, so moving noise to the front is penalised even though
# the set of chunks never changed.
ContextualPrecisionMetric(threshold=0.5, model="gpt-4o", include_reason=True).measure(case)

# Recall checks retrieval_context against expected_output — NOT actual_output.
# It asks "was enough fetched to SUPPORT the full answer", regardless of
# whether the generator actually used it.
ContextualRecallMetric(threshold=0.5, model="gpt-4o", include_reason=True).measure(case)

# Relevancy needs no ground truth at all — the only one of the three
# you can run against arbitrary production traffic.
ContextualRelevancyMetric(threshold=0.5, model="gpt-4o", include_reason=True).measure(case)
