3. Net Gaps Worth Closing

One theme repeated five ways: this repo has almost no first-party OpenAI agent-primitive coverage. The orchestration/guardrail/handoff/tracing depth is real — it's just expressed in LangGraph/CrewAI/AutoGen vocabulary, not OpenAI's own.

  1. Responses API & Agents SDK — 06_Agent_SDKs_First_Party/OpenAI_Agents_SDK/ is a placeholder folder with no notebooks.
  2. Computer Use — zero coverage; no analogue anywhere in the repo.
  3. Code Interpreter / Image Generation as hosted agent tools — model-level coverage exists (Phase 1), the tool-calling pattern doesn't.
  4. Human evaluation practice (blinded review, consensus voting) and adversarial/edge-case eval-set design — repo's eval strength is metrics and LLM-as-judge, not eval-set construction discipline.
  5. RLHF/DPO/LoRA and the eval → fine-tuning flywheel — explicitly planned, not built.
⚠ Why this pattern, not five isolated gaps Every OpenAI-specific gap traces back to the repo being framework-agnostic-in-practice (LangChain/LangGraph/CrewAI/AutoGen) rather than OpenAI-native. The architectural judgment underneath (routing, handoffs, guardrails, tracing) transfers directly — only the vocabulary and a few hosted-tool patterns (computer use, code interpreter, image gen as tool calls) are missing outright.
