# Theory & Reference

Companion material for the eleven notebooks in the parent folder.

## What this folder is — and deliberately is not

The notebooks already carry **~15,900 words of explanatory markdown**, about 60% of all
their content. The theory is not missing from them, and **these files do not repeat it.**

Mirroring those explanations here would create two copies of ~63 pages of prose, and
duplicated prose drifts. This repo has already been bitten by exactly that: `CLAUDE.md`
records that `README.md`'s tables "have historically drifted from `NOTEBOOK_INDEX.md`".
A per-notebook theory file would be the same mistake with more pages.

What the notebooks genuinely *cannot* do is **random access**. They are sequential: to look
up "when do I use quadratic weighted kappa?" you first have to know it lives in Phase 7.
So these files provide the things that exist in no single notebook:

| File | What it gives you | Why a notebook can't |
|---|---|---|
| `AGENT_UNDER_TEST.md` | What the agent actually **is** — functionality, tools, data, models, trace shape, and what it deliberately cannot do | Described in pieces across Phases 0, 1 and 9; nowhere as a whole |
| `CONCEPTS.md` | Every concept, defined in one or two lines, grouped **by theme** with a pointer to the phase that demonstrates it | Notebooks are ordered by build sequence, not by topic |
| `GOTCHAS.md` | Every trap hit while building the track — symptom → cause → fix | Each gotcha is stranded in the one notebook where it surfaced |
| `QUICK_REFERENCE.md` | The numbers, thresholds and decision rules worth memorising | Scattered across eleven files; nothing collects them |

## How to use it

- **Implementing something?** `GOTCHAS.md` first. Most of the entries cost an hour each to
  discover, and several are silent failures that look like success.
- **Revising for an interview?** `QUICK_REFERENCE.md` — it is deliberately compressible to a
  single sitting, and the numbers in it are the part that makes an answer concrete.
- **Trying to remember where something was covered?** `CONCEPTS.md` maps concept → phase.

The notebooks remain the explanation. These are the index, the warnings, and the recall
sheet.

## Keeping them honest

Every number in `QUICK_REFERENCE.md` was generated by running the track's own modules
(`conversation.py`, `monitoring.py`, `promotion.py`, `eval_dataset.py`) rather than
transcribed by hand, so they agree with the code by construction. If those modules change,
regenerate rather than edit.
