Planning Agent Pattern

plan → execute → check → replan if the world changed
PLAN IS REVISABLE MID-RUN
Plan
↓
Execute step N
↓
Check: still on track?
plan still valid → next step
plan invalidated → Replan
↓
Return
all steps complete
Planning Click any stage. Unlike a workflow orchestrator, the plan itself can be thrown out and rewritten mid-execution if a step reveals something the original plan didn't anticipate.
Who controls next stepThe plan — but the plan is model-authored and revisable
Cost / latencyHigher upfront (planning call) + variable execution
Failure modeThrashing — replanning repeatedly without progress
Typical guardrailCap on replan count; require the plan to shrink, not grow
