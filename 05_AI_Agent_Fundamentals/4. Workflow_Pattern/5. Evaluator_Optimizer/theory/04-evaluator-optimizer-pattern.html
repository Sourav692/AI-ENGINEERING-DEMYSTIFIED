Evaluator-Optimizer Pattern

generate → check against a fixed rubric → revise, bounded by a hard cap
FIXED RUBRIC, FIXED CAP
Generate
↓
Evaluate
(fixed rubric)
↓
rubric fails, rounds < cap — loop back to Generate
↓
Return
rubric passes, OR cap reached
Evaluator-Optimizer Click any stage. The rubric is fixed, enumerable code — not open-ended model judgment — and the round cap is the primary stop condition, known in advance.
Who controls next stepCode — fixed rubric decides pass/fail, fixed cap bounds the loop
Cost / latencyBounded — known maximum number of rounds
Failure modeRubric too strict (endless failing) or too loose (false pass)
Typical guardrailHard round cap; rubric versioned and testable independently
